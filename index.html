Engineering · voice AI platform

Self-serve voice agent creation

v1 and in-app Test Call are in production. Creating an agent: about 3 days → about 30 minutes.

Problem
Every client voice agent was built by hand in the console, and about 130 agents sat in one shared project with no separation between customers.
What I did
Wrote the creation layer in Python, Flask and React (about 6,500 lines): a client document becomes a configured Dialogflow CX agent, isolated to that customer, with code checks on every model output. Added Test Call so a new agent can be heard on a real call and fixed in the same screen.
Impact
Creation went from about 3 days to about 30 minutes, plus 3-4 hours of testing and tuning.
How it works
  • Two passes through an LLM: first extract a brief from the uploaded document, then generate a persona. Code renders it into the agent's goal and instruction steps and adds platform-wide rules.
  • Each agent is registered to one customer. Unregistered agents are invisible, and another customer's agent simply doesn't exist for you (a test customer sees 1 of about 130).
  • Platform settings are forced on every create or copy (timezone, speech settings, model, low temperature). A bad model reply gets up to 2 repair attempts, and nothing is created until the user saves.
  • Test Call dials through a platform-owned telephony account, tracks the call live, then reuses the existing transcript and summary screens. Capped per customer per day.
  • I built the authoring side for custom-LLM bots too (drafting, versions, summaries). The custom-LLM call runtime itself was built by teammates.

Engineering · reliability

Recruitment agents that finish the call

On a replayed live call, silent runs went from 7 of 8 to 0 of 8.

Problem
Generated agents returned no reply on 13-16% of turns, and recruitment calls often ended silently or judged candidates on criteria nobody approved.
What I did
HR picks and approves the screening questions; code builds the call flow; the LLM only writes the human parts.
Details
  • A job description drafts up to 10 questions, 5 marked as recommended. HR ticks, edits or adds them.
  • A question can reject a candidate only if HR switched that on for it. Every other answer is accepted.
  • HR reviews three sample calls (ideal, not ideal, edge case) before the agent is created.
  • On the same replay, judging remarks went from 32 to 0 and 8 of 8 runs reached the closing line.

Engineering · production reliability

Finding the bug before customers did

A fix that protected 134 of 170 bots across 35 customer databases from potential call failures.

Problem
Calls failed after completion for bots whose telephony provider name was stored with a capital letter. 134 of 170 bots were set up that way.
What I did
Traced it to case-sensitive routing and normalised the name before routing. I also audited 70 live bots' post-call summaries and built a generator that keeps each bot's summary prompt and intent list in sync.
Impact
The 134 bots route correctly. Campaign filters now match what the bots actually report.
Audit details
  • Of 70 bots: 16 had an empty intent list, 12 declared intents the prompt could never produce, and 19 had prompts producing undeclared intents.
  • The generator proposes intents from the bot's own instructions, the user confirms them, and code writes both the prompt and the intent list from that one spec, so they can't disagree.
  • "Fix with AI" patches an existing prompt by exact find-and-replace and shows a diff, so hand-written rules survive.
